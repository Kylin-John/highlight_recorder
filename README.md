# 高光回录（Highlight Recorder）

[![License: GPL-3.0](https://img.shields.io/badge/License-GPL--3.0-blue.svg)](LICENSE)
[![Android 8.0+](https://img.shields.io/badge/Android-8.0%2B-green.svg)](#环境要求与下载)

高光回录是一款 Android 游戏回放工具：游玩时持续缓冲最近一段屏幕画面，精彩时刻发生后，点击浮窗就能把此前的片段保存为 MP4。本 Fork 还提供接续保存、预计成片时长，以及通过 Shizuku 获取的游戏呈现帧率监测；可以边录边监测，也可以只监测、不录像。

**原作者：[owen88ob](https://github.com/owen88ob)，原项目：[highlight-recorder](https://github.com/owen88ob/highlight-recorder)。**

**本 Fork 的新增功能开发与维护：[Kylin（Kylin-John）](https://github.com/Kylin-John)，仓库：[highlight_recorder](https://github.com/Kylin-John/highlight_recorder)。**

本仓库保留原项目的作者署名、GPL-3.0 许可证及应用内原作者赞助入口。下文单独列出 Kylin 的贡献，区分原项目已有能力与 Fork 的新增功能；这些改动属于本 Fork，不代表已由上游合并或发布。

## 首次安装与开始回录

1. 安装对应版本 APK，打开「高光回录」，按引导授予悬浮窗、通知权限；Android 8～9 还需存储权限。
2. 根据需要允许应用后台运行。不同系统的选项可能称为「不限制」「允许后台活动」或电池优化白名单，具体入口以系统为准。
3. 打开「设置」，选择回退时长、保存模式、分辨率、录制帧率、码率与音频来源。初次可沿用默认的 **30 秒、720p、30 fps、8 Mbps、H.264**，再根据实际效果调整。
4. 如果也要查看游戏 FPS，先完成下文 Shizuku 配置，再在主页「监测游戏」选择将要游玩的游戏。**只需录像时可以不配置 Shizuku。**
5. 点击主页「开始循环录制」，同意系统屏幕录制弹窗，再切到游戏。每次新录制都需要系统同意；Android 14+ 的会话授权不能重复使用，见 [Android MediaProjection 文档](https://developer.android.com/media/grow/media-projection)。
6. 等待缓冲积累。出现想保留的片段时，单击浮窗，或点击通知中的「保存回放」、主页的保存按钮。
7. 根据提示确认保存成功，再到「视频库」查看。文件保存到公共视频目录 `Movies/高光回录/`，文件名形如 `高光_yyyyMMdd_HHmmss.mp4`。
8. 结束游戏后停止录制。若还想保存最后一段，先保存再停止，或使用「保存后停止录制」长按选项。

需要声音时，也要确认系统已允许本应用使用录音权限。系统可能将其显示为「麦克风」权限；Android 的播放音频内录同样要求 `RECORD_AUDIO`，仅允许屏幕录制并不等于已具备全部音频捕获条件。规则见 [Android 音频捕获文档](https://developer.android.com/media/platform/av-capture)。

主页的监测游戏只决定 **FPS 的目标**，不会把屏幕采集限定为该应用。切换游戏时，应先结束当前会话，在主页更换目标，再重新开始；软件不会自动把监测对象换成另一款前台游戏。

## 保存模式与停止方式

### 每次保存最近 N 秒（默认）

每次点击都从当前缓冲中取最近一段。连续两次点击间隔小于 N 秒时，两份视频会有重叠，适合分别保留单个精彩片段。刚开始录制、方向变化或缓冲被缩短时，可用内容可能不足 N 秒。

### 接续保存

在「设置 → 保存模式」选择「接续保存」。第一次保存仍取当前回退窗口；之后从上次成功保存处继续，且始终受 N 秒窗口限制。

例如设定 180 秒：

| 点击时刻 | 大致保存范围 |
| --- | --- |
| 第 5 分钟首次保存 | 第 2～5 分钟 |
| 第 6 分钟再次保存 | 第 5～6 分钟 |
| 下一次直到第 10 分钟才保存 | 第 7～10 分钟；更早内容已经离开缓冲 |

接续模式不能补回已被覆盖的内容，也不会把整场游戏无限保存在内存中。视频按可解码关键帧对齐，片段之间允许少量重叠与时长偏差。

保存的终点固定在点击时：例如 5:00 点击、5:08 导出完成，下次仍接续到 5:00 的媒体边界，导出期间新采集的内容继续留在缓冲中。失败不推进边界、不清空缓冲，可再次尝试；同一时刻只进行一次导出，重复操作不会排队。

### 「已缓存」与「预计生成」的区别

- **已缓存 X 秒**：当前环形缓冲实际保留的总量。
- **预计生成 X 秒视频**：现在点击保存，按当前模式和成功保存边界预计得到的成片长度。

接续保存后，预计成片可能很短，而缓存总量仍较大，这是正常现象。预计值复用实际媒体范围计算；不会为显示时长另做视频快照或复制视频载荷。

### 停止行为

| 操作 | 结果 |
| --- | --- |
| 长按浮窗，设置为「直接停止录制」 | 直接停止，不自动保存尚未导出的缓冲；这是默认选项 |
| 长按浮窗，设置为「保存后停止录制」 | 按当前保存模式导出，成功才停止；失败或暂无可保存画面时继续录制并提示 |
| 已在导出时长按「保存后停止」 | 提示本次完成后再次长按；不并发、不排队，也不提前停止 |
| 主页或通知栏点「停止」 | 直接停止，不受浮窗长按选项影响 |

停止后重新录制、屏幕旋转或自动恢复导致编码器重建时，新的缓冲与接续边界重新开始；不要把这些操作理解为无缝接续同一媒体片段。

## 浮窗的显示与操作

在「设置 → 浮窗显示内容」三选一，选择会持久保存：

| 显示内容 | 录制会话 | 独立监测会话 |
| --- | --- | --- |
| 「存」 | 显示「存」 | 显示「存」，点击行为仍为查看详情 |
| 游戏呈现 FPS 数值 | 有有效监测数据时显示数值，否则显示 `—` | 同左 |
| 预计生成视频的秒数 | 显示当前预计成片秒数 | 显示 `—`，因为没有录像 |

浮窗主体仅显示一个汉字或数值，不附加单位文字。选择「存」或预计秒数也不会停止当前会话的 FPS 采样；切换显示不会重置统计或重复启动采样。

| 会话 | 单击浮窗 | 长按浮窗 |
| --- | --- | --- |
| 循环录制（可同时监测） | 保存回放 | 按设置直接停止，或保存成功后停止 |
| 独立监测（未录像） | 打开监测详情 | 结束监测并保留报告 |

拖动浮窗可移动，松手后贴近屏幕左右边缘；位置会保留。设置中可调整透明度、大小和贴边半隐藏。彻底隐藏后会话继续运行，可从设置恢复，或通过通知与应用页面操作。完全透明时浮窗仍可能接收点击。

## 搭配 Shizuku 使用帧率监测

普通应用权限无法直接读取其他游戏的呈现帧数据。本功能借助 **Shizuku 的授权服务**，只读查询目标游戏的 SurfaceFlinger 画面图层；root 不是必需条件。Shizuku 的安装、启动与授予本应用权限是三个步骤，**仅安装 Shizuku 还不够**。

Shizuku 只用于监测，不会代替系统屏幕录制授权，也不会解锁游戏帧率或修改手机刷新率。

### 1. 安装并启动 Shizuku

从 [Shizuku 官方下载页](https://shizuku.rikka.app/zh-hans/download/) 获取应用。本项目需要运行中的 **Shizuku 12 或更新版本**；依赖表中的 `Shizuku API 13.1.5` 是开发库版本，不是要求安装某个同号 APK。

| 启动方式 | 适用情况 |
| --- | --- |
| 无线调试 | Android 11+，通常无需电脑，推荐先查看此方式 |
| 电脑 ADB | 未 root 的较早 Android 系统，或无线调试不可用时 |
| 已有 root | Shizuku 自身支持的另一种启动方式；本项目不要求为此 root 手机 |

具体界面和厂商差异以 [Shizuku 官方用户手册](https://shizuku.rikka.app/zh-hans/guide/setup/) 为准。

**Android 11+ 无线调试流程：**

1. 根据系统要求连接 Wi-Fi，在系统设置中开启「开发者选项」，按 Shizuku 提示开启 USB 调试与无线调试。
2. 在 Shizuku 的无线调试入口选择配对，并允许其显示通知。
3. 打开系统「无线调试」，选择使用配对码配对设备。
4. 将系统显示的配对码输入 Shizuku 的配对通知，完成配对。
5. 回到 Shizuku，执行启动，确认首页显示服务正在运行。

配对成功不等于服务已经启动。通常不必每次重新配对，但非 root 方式在手机重启后需要重新启动服务；服务被系统终止后也需要恢复。无线调试或厂商系统的问题请优先对照官方手册排查。

**需要电脑 ADB 时：** 按官方手册准备 Android SDK Platform-Tools、启用 USB 调试并确认电脑授权，再运行 Shizuku 当前提供的启动命令。使用 Shizuku 界面显示的命令，避免套用不适用于当前安装版本的脚本路径。ADB 的连接与授权说明见 [Android 官方文档](https://developer.android.com/tools/adb)。本应用不会自行安装或启动 ADB。

### 2. 授予「高光回录」Shizuku 权限

1. 确认 Shizuku 显示正在运行。
2. 打开高光回录，进入「游戏帧率监测 / 最近报告」。如提示未授权，点击「请求 Shizuku 授权」，在弹窗中允许。
3. 也可在 Shizuku 的应用管理中检查授权状态，确认授权的是当前安装的 Fork。旧包可能显示「高光回录·接续测试」，当前包显示「高光回录」；包名仍为 `com.highlightrecorder.continuationtest`。
4. 回到高光回录，确认未运行、未授权等提示已经消失。

新安装的不同包名应用需要单独授权；不要把给原版的授权当成已给 Fork 授权。

### 3. 在主页选择游戏

在主页「开始循环录制」与「游戏帧率监测 / 最近报告」之间的 **「监测游戏」** 选择目标。列表按本应用内的监测会话次数与最近使用排序，常用游戏逐渐靠前；选择会保存，不读取系统全部应用的使用历史。

选择是显式的，不随前台游戏自动变化。开始录制或监测后，目标会被锁定；要换游戏，先结束当前会话，再回主页更换。监测详情页只显示当前或本次游戏，不能在那里修改。

### 4. 选择运行方式

**只监测、不录像：**

1. 主页选好游戏，进入「游戏帧率监测 / 最近报告」。
2. 点击「开始独立监测」。基础悬浮窗与通知权限仍需开启。
3. 切到所选游戏，进入实际游戏画面，等待有效采样。若希望游戏内看到 FPS，在设置中把浮窗显示改为 FPS。
4. 游玩结束后长按浮窗、点击通知的停止，或返回监测页点击「结束监测并保留报告」。

独立监测不申请 MediaProjection，不启动屏幕采集、音视频编码器或录像缓冲。它与录制会话互斥，切换前需先结束当前会话。

**一边回录、一边监测：**

1. 主页选好游戏，然后点击「开始循环录制」，同意系统录屏授权。
2. 切到该游戏，FPS 采样随录制会话运行；浮窗点击仍用于保存回放。
3. 停止录制时，同时结束对应监测并生成最近报告。

缺少 Shizuku 授权或有效帧数据时，录制本身仍可使用；FPS 显示 `—`，不会用视频编码帧率代替。

### 5. 查看曲线和报告

回到监测页会更新当前统计，也可点击「更新统计」。正常结束后，在「最近结束的会话」查看曲线、均值、1% low、有效监测时长、统计范围和中断次数。

**均值与 1% low 基于最近保留的有效数据，最多最近 5 分钟，不是整场长对局的全程统计。** 中断不补帧，缺失曲线不连线。最近完成的报告保存在本应用内部，新完成报告替换旧报告；当前没有多场历史列表或报告导出。

自动图层选择通常无需干预：优先唯一 BLAST 画面图层，并记住真正产生过有效 FPS 的图层特征。如果有多个候选，展开「图层与诊断」，明确选择所选游戏的画面图层，再回游戏继续观察；带 BLAST 的 SurfaceView 可作为优先检查对象，但名称本身不保证有效。

完整的数据来源、1% low 算法、采样开销与缺口规则见 [FPS 数据与统计说明](docs/FPS_MONITORING.md)。

## 设置参考

设置会持久保存。录制的分辨率、编码目标等参数主要在下次开始录制时读取；浮窗显示与外观可在当前会话中更新。

| 设置 | 选项或范围 | 使用说明 |
| --- | --- | --- |
| 回退时长 | 15～300 秒 | 更长窗口占用更多内存；主页会显示当前实际缓存和预计成片时长 |
| 保存模式 | 最近 N 秒 / 接续保存 | 默认最近 N 秒；接续也受窗口限制 |
| 分辨率 | 跟随屏幕、720p、1080p、2K、4K | 按目标短边保持比例，不放大超过屏幕实际尺寸；编码器不支持时会缩小 |
| 录制帧率 | 30 / 60 / 90 / 120 fps | 视频编码目标，不代表游戏 FPS；高档位受屏幕供帧和编码器性能限制 |
| 码率 | 低 4 / 中 8 / 高 16 Mbps，自定义 1～60 Mbps | 更高码率通常增加文件体积与缓冲内存；高分辨率、高帧率宜配合足够码率 |
| 编码器 | H.264 / 支持时显示 H.265（HEVC） | H.265 是否可用取决于设备，播放与分享端也需要支持 |
| 音频来源 | 内录、麦克风、内录+麦克风、静音 | 内录需 Android 10+；采集音频需相应录音权限，且目标允许捕获 |
| 浮窗显示内容 | 存 / FPS / 预计视频秒数 | 不影响后台采样是否运行；无有效数值时显示 `—` |
| 浮窗长按行为 | 直接停止 / 保存后停止 | 仅作用于录制浮窗；独立监测中长按始终结束监测 |
| 浮窗外观 | 隐藏、透明度 0～100%、大小 0.75～1.5 倍、贴边半隐藏 | 隐藏不会停止会话，可从设置恢复 |
| 回收站保留 | 1～90 天，默认 30 天 | 打开视频库或回收站时检查并清理过期项目 |

设置选中项使用主题色边框、底色和勾选标记，选项在空间不足时换行，明暗主题跟随系统。

## 视频库与回收站

主页进入「视频库」，可查看缩略图、视频时长与文件大小，调用系统中可用的播放器播放，或通过分享面板发送文件。长按进入多选，可全选、批量分享或删除。

删除操作会先确认，再把文件移到 `Movies/高光回录/回收站/`。在回收站可恢复到视频库，也可确认后彻底删除或清空；彻底删除无法在本应用内撤销。到期清理由进入视频库或回收站时触发，不是持续运行的定时清理服务。

视频文件、回收站和最近 FPS 报告是不同的数据：结束监测不会生成视频，清除应用数据或卸载可能丢失设置、回收站时间记录和内部监测报告。需要保留的文件应先自行备份。

## 常见问题

| 现象 | 检查方法与含义 |
| --- | --- |
| FPS 一直显示 `—` | 先确认版本包含监测功能，再确认 Shizuku 正在运行、当前包已授权、主页选择的是正在玩的游戏，并进入该游戏的实际画面。仍不可用时展开「图层与诊断」查看具体问题 |
| 返回高光回录后提示等待游戏 | 正常：统计目标不在前台时暂停，回到所选游戏后重新建立基线；不要把当前应用页面的帧率算到游戏中 |
| 换了游戏却没有 FPS | 先结束当前会话，在主页更换「监测游戏」；软件保留上次选择，不自动跟随所有前台应用 |
| 需要手动选择图层 | 自动选择无法唯一判定时的处理入口；选择目标画面图层后回游戏观察。没有有效呈现时间戳的图层不能靠选择操作变成可测 |
| 安装 Shizuku 后仍提示未运行 | 还需要启动服务并授权本应用；非 root 方式重启手机后通常要重新启动服务 |
| 页面能采样，但 1% low 是 `—` | 有效帧间隔少于 100 个时不计算；均值与 low 的定义见统计说明 |
| 曲线有空白，或有效时长小于会话时长 | 切后台、关屏、权限或连接中断、图层变化、时间戳缺失都可能造成缺口，缺失时段不纳入均值 |
| 保存后的接续视频比缓存短 | 正常：缓存是保留总量，接续只导出尚未成功保存且仍在窗口内的部分 |
| 录下的视频无声 | 检查音源与系统录音权限。Android 内录还需目标应用允许捕获；混音一路无法建立时可退为单路，初始化或运行异常可能继续无声录制并提示。系统返回静音数据时不一定出现错误提示，见 [Android 音频捕获限制](https://developer.android.com/media/platform/av-capture) |
| 旋转后缓存重新开始 | 编码器需要重建，旧缓冲和接续边界随之重置；新片段需重新积累 |
| 高分辨率或高帧率未达到设定值 | 设置是目标，设备可能缩小分辨率或无法供给目标帧率；先降低参数并对照实际结果 |
| 后台被停止或浮窗消失 | 检查隐藏/透明度设置、悬浮窗授权、系统后台限制和通知中的异常；必要时重新开始会话 |
| 视频黑屏 | 受保护内容、系统策略或屏幕采集异常可能导致；本应用不绕过内容保护 |

FPS 监测只读取数据，不修改游戏配置、手机刷新率、性能策略或厂商插帧。它没有超频、解锁帧率或游戏性能增强功能。采样和录像都可能增加耗电、发热与负载，实际影响需要在同一设备与配置下对照测量。

## 权限与本地数据

| 权限或授权 | 用途 |
| --- | --- |
| 悬浮窗 `SYSTEM_ALERT_WINDOW` | 在游戏画面上显示可操作的浮窗 |
| 屏幕录制 MediaProjection | 每次录制会话取得用户同意，采集屏幕及允许的播放音频；独立监测不申请 |
| 通知 `POST_NOTIFICATIONS`（Android 13+） | 显示运行状态、保存结果与停止入口 |
| 录音 `RECORD_AUDIO` | 音频采集，包括麦克风、混音及 Android 播放音频捕获所需权限；仅监测 FPS 不采集音频 |
| 存储 `WRITE_EXTERNAL_STORAGE`（Android 8～9） | 保存和管理公共视频；Android 10+ 通过 MediaStore 访问相应媒体 |
| 电池优化白名单（可选） | 帮助会话在后台持续运行，不保证规避所有系统后台策略 |
| Shizuku 授权（监测可选） | 读取前台目标、图层列表和呈现时间戳；拒绝后仍可使用普通回录 |
| 前台服务类型 | 录制使用 mediaProjection，使用麦克风时包含 microphone；独立监测使用 specialUse |

视频存储在公共视频目录；设置、常用排序、成功图层偏好和最近报告存储在本机。最近报告排除系统自动备份。应用保留有大小上限的本地运行诊断日志，当前没有账号、云同步或自动上传遥测；主动播放、分享和打开赞助链接会交给外部应用处理。

## 构建与工程验证

### 构建环境

- 完整 **JDK 17 或更新版本**，包含 `java`、`javac`、`jlink`；Android SDK Platform 35。
- 项目使用 Gradle Wrapper 8.10.2、Android Gradle Plugin 8.7.3、Kotlin 2.0.21、Compose；构建版本以 Gradle 配置为准。
- 用 Android Studio 配置 SDK，或在未提交的 `local.properties` 设置自己的 `sdk.dir`。SDK、签名材料与本地路径不应提交到仓库。
- 首次构建需要获取 Gradle 与 Maven 依赖；已缓存完整依赖后才可使用离线模式。

在项目根目录执行：

```bash
bash ./gradlew testDebugUnitTest assembleDebug
```

Gradle 产物为 `app/build/outputs/apk/debug/app-debug.apk`；发布附件与本地交付文件命名为 `HighlightRecorder-v1.2.3.6-debug.apk`。`dist/` 不跟踪进 Git，构建本身不会创建 GitHub Release。

debug 构建保留 `.continuationtest` 包名后缀；release 构建未使用该后缀。覆盖更新要求包名、签名与版本规则匹配，自行构建时不能仅凭 APK 文件名判断能否覆盖已有安装。

### 工程验证范围

1.2.3.6 的现有工程验证为 **91 项 Android JVM 单元测试通过、`assembleDebug` 成功、APK 版本与签名校验通过**。测试覆盖保存模式、预计时长、失败与并发处理、会话隔离、设置映射、采样生命周期、实际呈现时间戳解析、均值与 low、图层匹配、常用排序和浮窗内容。

测试使用合成时间戳、Preferences 映射、协程和仿真进程；它们不等于设备权限、实际游戏 FPS 精度或功耗评估。详细数据定义和对应测试见 [FPS 数据与统计说明](docs/FPS_MONITORING.md)。
