# FPS 数据与统计说明

本文件对应本 Fork 1.2.3.6 的监测实现，用于解释报告含义与工程边界。安装、Shizuku 配置和日常操作见 [README 的使用教程](../README.md#搭配-shizuku-使用帧率监测)。本功能由 [Kylin / Kylin-John](https://github.com/Kylin-John) 在原高光回录项目上新增。

## 实际测量的是什么

数据来源为 **SurfaceFlinger 所选游戏图层 `--latency` 输出的第二列 `actualPresentTime`**。使用有效、连续的实际呈现时间戳计算帧间隔，再得到 FPS。

| 指标 | 本功能如何处理 |
| --- | --- |
| 所选游戏图层的实际呈现 FPS | 本功能的统计来源，前提是系统提供有效时间戳且选中正确的画面图层 |
| 屏幕刷新率 | 不是游戏 FPS；`--latency` 第一行的刷新周期不用于生成游戏 FPS |
| 屏幕采集或视频编码 FPS | 录制流水线的指标，不能代表目标游戏实际呈现；不会用编码参数或包数量补值 |
| 高光回录自身界面 FPS | 不作为其他游戏的监测来源，不使用本应用的 Choreographer 帧率代替 |

所选图层的呈现信息不能单独确认厂商插帧后的实际扫描输出，也不是游戏引擎内部的渲染性能计数器。本功能不修改帧率上限、刷新率、游戏配置或性能策略。

## 权限与目标识别

普通应用权限不足以取得其他应用的这些信息。应用要求 **Shizuku 12+** 正在运行并已授权，通过 UserService 使用其 shell/root 身份；推荐不需 root 的无线调试或电脑 ADB 启动方式。具体操作见 [Shizuku 官方手册](https://shizuku.rikka.app/zh-hans/guide/setup/)。

监测桥接只执行三类固定读取：

```text
dumpsys window displays
dumpsys SurfaceFlinger --list
dumpsys SurfaceFlinger --latency <所选图层>
```

前台焦点必须能确认属于主页选定的包名，才读取其候选图层并统计。返回本应用、切换其他应用、关屏，或无法唯一确认目标时暂停。多窗口、系统浮层和厂商实现可能影响焦点识别；不能确认时不把其他画面算到目标游戏中。

独立监测无需屏幕录制授权，也不创建音视频编码器或录像缓冲。录制附带监测时，两者属于同一服务会话；停止录制会结束对应监测。录制与独立监测不能作为两个并行会话启动。

## 图层如何选择

1. 按主页选定的应用筛选当前图层，排除明显的启动、过渡、遮罩和输入辅助图层。
2. 如果已有该应用真正产生有效 FPS 的成功特征，优先重新匹配其类型与窗口组件。
3. 没有可用成功匹配时，优先唯一的 SurfaceView BLAST 画面图层，再尝试其他可唯一确定的画面候选。
4. 无法唯一确定时等待用户在「图层与诊断」中手选，不按句柄、日期或编号猜选。

成功特征按应用隔离保存，不保存易变的完整图层名。只点击图层、只有刷新周期头或采样失败，不会被记为成功。手选图层重建后也可按稳定特征重新匹配；实际图层变化会使统计断开并重新建立基线。

常用排序基于本应用内开始过的监测会话次数与最近使用时间，包括录制附带的监测。它不读取系统全局应用使用记录，也不补造安装前的使用次数。

## 采样、刷新与资源

| 项目 | 当前策略 |
| --- | --- |
| 正常目标图层读取 | 最快每 500 ms 一轮，命令执行耗时也计入周期，不并发积压 |
| 无目标、关屏或权限不可用 | 通常每 2 秒检查一次 |
| 图层列表 | 最多约每 2 秒刷新一次 |
| 实时发布与曲线点 | 通常约每秒更新一次；状态变化可提前发布 |
| 实时数值过期 | 超过 1.5 秒没有新鲜发布时清除数值，由共享的 500 ms 服务 ticker 检查 |
| 原始统计保留 | 最近 5 分钟内，最多 72,000 个有效帧间隔 |
| 曲线保留 | 最近 5 分钟内，最多 300 个点 |
| 统计排序 | 查看/更新报告或结束会话时计算 low；不在每次采样时对全量间隔排序 |
| 落盘 | 正常结束时写入有限报告，不连续写原始帧间隔 |

帧间隔的两组 LongArray 约占 1.1 MiB，这只是原始数组，不代表整个应用或监测服务的总内存。命令有执行时限和输出长度上限，Shizuku 连接在会话结束后释放。

同一会话只有一个采样循环。浮窗选择「存」、FPS 或预计秒数，只改变显示内容，不另起循环或重置统计；服务中的共享刷新也不为每种显示单独创建任务。旧会话或旧图层选择的迟到结果不能更新当前会话。

这些策略用于限制工作量，不能仅据此宣称低功耗、无游戏影响或达到桌面性能监测工具的同等能力。录像本身另有持续采集和编码负载，独立监测与录制附带监测的开销需要分别测量。

## 统计定义

### 有效帧间隔

从同一连续段的相邻有效呈现时间戳得到间隔 `dt = t[i] - t[i-1]`。以下情况不制造跨越缺口的间隔：

- 首次采样、重新连接、恢复目标或切换图层：先建立基线。
- 已观察到目标不在前台、关屏、权限或连接中断。
- 时间戳无效、格式不支持，或有效记录中间存在缺口。
- SurfaceFlinger 自身有限历史已覆盖上次读取的帧：只使用本批内部能确认的连续间隔。

无效值、空槽或待呈现哨兵不作为真实呈现帧。长时间没有新有效数据时显示 `—`，不会输出伪造零帧，也不会用其他指标补成连续曲线。

### 实时 FPS

在当前连续段中，取**结束时间处于最近 1 秒内**的有效帧间隔：

```text
实时 FPS = 间隔数量 / 间隔总时长（秒）
```

浮窗将数值显示为整数，详情页保留一位小数。采样与显示都有时间窗口，因此它不是每一个瞬间独立测得的帧率。

### 均值

对当前保留范围内的全部有效帧间隔计算：

```text
均值 FPS = N / sum(dt)
```

`dt` 在公式中以秒计。缺口不进入分母，因此均值不等于「整场会话所有墙钟时间上的平均」，也不等于曲线上每秒 FPS 点的算术平均。

### 1% low

当有效间隔数 `N >= 100` 时，取最慢的 `ceil(N × 0.01)` 个间隔，求其平均时长的倒数：

```text
k = ceil(N × 0.01)
1% low FPS = k / sum(最慢 k 个 dt)
```

少于 100 个有效间隔时显示 `—`。该定义不同于 FPS 的第 1 百分位，也不同于最慢 1% 瞬时 FPS 的算术平均；不同工具的 low 值必须先核对算法、范围、采样来源和缺失处理，不能直接混合比较。

### 会话时长、有效时长与统计范围

- **会话时长**：从开始到当前或正常结束的时间，可能包含等待和后台时段。
- **有效监测时长**：当前保留的有效帧间隔时长之和，不包含缺口。
- **统计范围**：这些有效间隔在本次会话中的起尾秒数；范围内部仍可能有缺失。
- **中断次数**：会话累计的断开或历史覆盖次数，与最近曲线窗口不是一一对应。

超过 5 分钟的会话仍可以继续，但均值、low 与曲线仅基于有限的最近数据；高帧率达到 72,000 间隔上限时，统计范围还可能短于 5 分钟。不能把十几分钟会话的最终报告当作整场完整测量。

## 曲线和最近报告

曲线横轴为会话起点后的秒数，纵轴为 FPS，显示实际轴范围。缺失点留空；中断两侧不连线，没有有效曲线时明确显示无数据。

进入或返回监测页时更新当前统计，也可手动「更新统计」；均值和 low 不承诺每秒重新计算。正常结束时保存最近一份有限报告，包含目标、会话时长、统计摘要、曲线、中断与最近诊断，不包含原始视频或逐帧日志。

报告放在应用内部的 `noBackupFilesDir`，排除系统自动备份；新完成报告替换上一份，没有多场归档、云同步或复杂导出。进程被系统直接终止时，未正常结束的会话不保证生成完整报告；清除应用数据或卸载会丢失内部报告。

## 可用性与验证边界

Shizuku 授权成功只证明具备桥接条件，不能证明系统一定提供有效呈现时间戳。厂商可能拒绝读取、只返回刷新周期或空槽，图层也可能没有可用历史；这些情况应显示不可用并保留诊断。

源码和 JVM 测试覆盖时间戳解析、缺失与历史边界、统计、采样循环、显示独立、旧回调、图层匹配及设置排序等行为；设备上的权限、图层数据有效性、游戏测量精度与额外功耗，需要相应设备与对照条件验证。
